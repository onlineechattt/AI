# lilbulle POS เว็บ V12.1.7 / หลังบ้าน V12.1.6
28 ตุลาคม 2569

แก้ป้ายเวอร์ชันการเคลื่อนไหวจากข้อความ V${APP_VERSION} เป็นเลขเว็บจริง
เพิ่มข้อความผิดพลาดในหน้าต่างปิดยอดโดยตรง เพื่อให้อ่านเหตุผลได้ขณะเปิดหน้าต่าง

สาเหตุจริงที่ผู้ใช้ปิดไม่ได้ยังไม่ได้รับข้อความผิดพลาดหรือทำซ้ำในเบราว์เซอร์จริง จึงยังไม่ถือว่าแก้สาเหตุปิดยอดไม่ได้สำเร็จ

# lilbulle POS V12.1.6 — ตัวตรวจโควตา LINE
วันที่ 28 ตุลาคม 2569

## สิ่งที่เพิ่ม
- เว็บ: จัดการ → ตรวจโควตา LINE
- อ่านโควตาเป้าหมายและยอดใช้โดยประมาณผ่าน LINE API ด้วย Token เดิม
- แสดงเวลาตรวจ ยอดคงเหลือโดยประมาณ จำนวนข้อความค้างทุกบูธ และข้อผิดพลาด 5 รายการล่าสุดที่ยังค้าง
- ตั้งแต่ติดตั้งรุ่นนี้ การส่งที่ล้มเหลวจะเก็บข้อความตอบกลับจาก LINE ใน NotifyError ด้วย ไม่ใช่เพียง HTTP 429
- ไม่สามารถกู้รายละเอียดการตอบกลับของการส่งเก่าที่บันทึกเพียง HTTP 429 ได้ จะแสดงว่ายังระบุสาเหตุไม่ได้
- ข้อมูลโควตา API เป็นค่าประมาณ และ “none” หมายถึงไม่ได้ระบุเป้าหมาย ไม่ใช่รับรองว่าส่งไม่จำกัด
- ตัวตรวจอ่านอย่างเดียว ไม่ส่ง LINE ไม่แก้บิล ไม่แก้สต๊อก ไม่สร้างชีท ไม่เพิ่มการเรียก API ตอนเปิดร้านหรือบันทึกขาย
- ใช้สิทธิ์บอสหรือทีมงานที่ล็อกอินแล้ว ผ่านตัวกลาง Netlify เดิม ไม่เปิด Token ให้เบราว์เซอร์
- คงหน้าเว็บ V12.1.5 เดิม รวม QR และไม่มีตัวละคร รุ่นนี้ไม่ได้เปลี่ยนวิธีโหลดรูปสินค้า

## ขั้นที่ 1 — Apps Script
1. เปิดโปรเจกต์ lilbulle เดิม สำรองไฟล์ BoothPOS_V11.gs เดิมไว้
2. เปิดไฟล์ apps-script/BoothPOS_V11.gs ในชุดนี้ คัดลอกทั้งหมดไปแทนเนื้อหาไฟล์ BoothPOS_V11.gs เดิมทั้งไฟล์
3. อย่าสร้างไฟล์ซ้ำอีกอัน อย่าแทน Code.gs หรือไฟล์ระบบสต๊อกอื่น และอย่าเปลี่ยน Script Properties
4. กดบันทึก เลือกฟังก์ชัน lbCheckLineQuota แล้ว Run เพื่อดูผลทันทีได้ (ฟังก์ชันนี้ไม่ส่ง LINE)
5. ดูบันทึกการดำเนินการ ผลเป็น used, limit, remaining, errors และ failures ไม่ต้องส่ง Token ให้ใคร
6. เพื่อเรียกจากเว็บ ให้ Deploy → Manage deployments → เลือก Web app เดิม → รูปดินสอ → Version: New version → Deploy
7. ใช้ deployment เดิมและ URL /exec เดิม ไม่ต้องสร้างโปรเจกต์ใหม่

## วิธีตรวจ
จัดการ → ตรวจโควตา LINE → อ่านผล สามารถกด “ตรวจอีกครั้ง” ได้เมื่อต้องการ ไม่ควรกดรัว
- ใช้ไปโดยประมาณ/โควตาเป้าหมาย/คงเหลือโดยประมาณ: มาจาก LINE API
- MONTHLY_LIMIT: ข้อผิดพลาดครั้งก่อนระบุ monthly limit ให้ตรวจแพ็กเกจ/ยอดใช้ของ OA
- RATE_LIMIT: ข้อผิดพลาดครั้งก่อนระบุ Too many requests หรือ rate limit ให้ลดความถี่การส่ง
- UNKNOWN_429: เก็บแค่ HTTP 429 จึงยังแยกสาเหตุไม่ได้ แม้ตรวจโควตาได้แล้ว
- AUTH: ตรวจสิทธิ์และ Token ของ OA โดยไม่เปลี่ยนข้อมูลขาย
ผลจากครั้งก่อนอาจต่างจากสถานะปัจจุบัน ยอดคงเหลือบวกไม่รับรองการส่งสำเร็จ
หากโควตาเต็ม ตัวตรวจไม่เพิ่มโควตาและไม่ปลดข้อจำกัด LINE ต้องจัดการบัญชี OA ก่อน
