# lilbulle Booth POS V11.0 — ชุดติดตั้งแยกสำหรับ Netlify

สถานะ: จัดทำโค้ดและโหมดทดลองแล้ว ยังไม่ได้ติดตั้งลง Apps Script / ชีทจริง หรือเผยแพร่เว็บบน Netlify และยังไม่ได้ทดสอบการส่งเข้ากลุ่มจริง
วันที่จัดทำ: 24 ตุลาคม 2569

## เปิดดูและทดลองก่อน

เปิดไฟล์ Lilbulle_POS_Preview.html ด้วย Chrome / Edge / Safari แล้วกด “ลองร้านตัวอย่าง”
หากเปิดผ่านตัวดูไฟล์ใน iPhone แล้วกดไม่ได้ ให้เปิดผ่านเว็บเบราว์เซอร์หรือให้ผู้ดูแลนำโฟลเดอร์ public ไปโฮสต์เป็นเว็บตัวอย่าง
ราคา จำนวนสินค้า และชื่อบูธในโหมดนี้เป็นข้อมูลสมมติ ไม่อ้างอิงราคาจริง
ทดลอง: ตรวจรับสินค้าล็อตละ 24 → กดเลือกสินค้า → ยืนยันรับเงิน → ดูรายการขาย → ปิดยอดรายวัน
หน้าร้านแสดงลูกค้าเดินมา พนักงานจัดของ และลูกค้าออกเมื่อบันทึกขายสำเร็จ ปิดฉากร้านได้

## โครงสร้างไฟล์และต้องวางตรงไหน

| ไฟล์ | วิธีใช้ |
|---|---|
| apps-script/Code.gs | แทนเนื้อหาไฟล์ Code.gs เดิมทั้งไฟล์ ในโปรเจกต์ Apps Script เดิม หลังสำรองโค้ดเดิมไว้ |
| apps-script/BoothPOS_V11.gs | เพิ่มไฟล์สคริปต์ใหม่ในโปรเจกต์ Apps Script เดียวกัน ชื่อ BoothPOS_V11 |
| apps-script/Index.html | สำเนาหน้าสต็อกเดิม ไม่ได้แก้ หากมีอยู่แล้วไม่ต้องวางทับ |
| apps-script/POS.html | สำเนา POS รุ่นเดิมไว้เก็บประวัติ ไม่ใช่หน้าเว็บ POS รุ่นใหม่ |
| public/ | หน้า POS ใหม่ โฮสต์บน Netlify |
| netlify/functions/pos.mjs | ตัวกลางตรวจสิทธิ์ ไม่เปิดเผย API key ต่อเบราว์เซอร์ |
| netlify.toml | การตั้งค่า build / functions / security headers |
| tests/ | ทดสอบตรรกะสต็อก บิล ปิดยอด และสิทธิ์ โดยไม่แตะชีทจริง |

สำคัญ: เพิ่ม BoothPOS_V11.gs ในโปรเจกต์เดิม ไม่สร้าง Apps Script อีกโปรเจกต์ เพราะต้องใช้ Script Lock ตัวเดียวกับระบบสต็อกในการเบิก/คืน
ไม่ต้องสร้างชีทใหม่ทั้งไฟล์ ระบบใช้ SS_ID เดิม และเพิ่มแท็บ LilbullePOS_V11 เท่านั้น พร้อมใช้ BoothPOS_Products ที่มีอยู่

## เปลี่ยนอะไรใน Code.gs เดิมบ้าง

1. เพิ่มตัวแยกคำขอ POS ใหม่ใน doPost ก่อนเข้า LINE webhook เดิม
2. ใบคืนบูธหักจำนวนที่ POS V11 ขายไปแล้วออกจากจำนวนที่คืนได้ แยกตาม SKU / Exp และกันรายการคืนซ้ำล็อตเดียวในคำขอเดียว
3. POS รุ่นเก่าไม่รับบิลเพิ่มสำหรับใบเบิกที่ตรวจรับเข้า V11 แล้ว เพื่อกันใช้สองระบบซ้อน
ฟังก์ชันสต็อกอื่น และหน้าสต็อกเดิมเก็บไว้ตามไฟล์ที่บอสส่งมา

## ติดตั้งฝั่ง Apps Script

1. สำรอง Code.gs เดิมก่อน แทนด้วย apps-script/Code.gs และเพิ่ม BoothPOS_V11.gs ตามตารางด้านบน
2. เก็บ Script Properties เดิมทั้งหมด: SS_ID, ACCESS_TOKEN, GROUP_ID, BOSS_PIN และค่าที่ระบบเดิมใช้งาน
3. เพิ่ม Script Properties ดังนี้ (อย่าส่งค่า PIN หรือ token ลงแชท)

| ชื่อ | ค่า |
|---|---|
| POS_API_KEY | รหัสสุ่มยาวอย่างน้อย 32 ตัวอักษร ตั้งเอง เก็บเป็นความลับ และใช้ตรงกับ Netlify |
| POS_TEAM_PIN | PIN สำหรับพนักงาน แยกจาก BOSS_PIN แนะนำอย่างน้อย 6 หลัก |
| POS_GROUP_ID | Group ID ของกลุ่ม LINE ใหม่สำหรับยอดจาก POS เท่านั้น |
| POS_LINE_ACCESS_TOKEN | ไม่บังคับ หากใช้ OA เดียวกับเดิม ระบบใช้ ACCESS_TOKEN เดิมได้ |
| POS_UPLOAD_FOLDER_ID | ID ของโฟลเดอร์ Google Drive ที่จะเก็บรูปสินค้าและไฟล์แนบ |

บอท LINE ต้องอยู่ในกลุ่มใหม่ และ channel token ต้องเป็นของบอทนั้น
GROUP_ID เดิมยังเป็นกลุ่มของระบบสต็อก ส่วน POS ใช้ POS_GROUP_ID แยกกัน
หากยังไม่ตั้งค่า LINE บิลจะยังบันทึกได้ และข้อความค้างรอให้แอดมินกดส่งใหม่

4. เลือกฟังก์ชัน setupLilbullePOSV11 แล้วกด Run หนึ่งครั้ง ยอมรับสิทธิ์ Google Sheets / Drive / การเรียกบริการภายนอกตามบัญชีผู้ดูแล
5. Deploy → Manage deployments → แก้ไข Web App deployment เดิม → New version → Deploy ใช้ Execute as ผู้ดูแล และตั้ง access ให้ Netlify เรียกได้ตามนโยบายบัญชี (โดยทั่วไป Anyone) API POS เองยังต้องใช้ POS_API_KEY และสิทธิ์ session
6. คัดลอก URL ลงท้าย /exec เพื่อใส่ Netlify ไม่ใช้ URL /dev
7. ฟังก์ชันเก่าที่เปิดผ่าน google.script.run ยังมีพฤติกรรมและสิทธิ์เดิม ชุดนี้ไม่ได้เปลี่ยนสิทธิ์ของระบบเก่าทั้งระบบ

## ติดตั้ง Netlify

เว็บนี้มี serverless function: ให้ deploy จาก Git repository หรือ Netlify CLI จากโฟลเดอร์รากของชุดนี้
การลากเฉพาะ public ลง Netlify Drop ทำได้เพียงหน้า static/โหมดทดลอง ไม่ได้ติดตั้งตัวกลางขายจริง
ไม่ต้องมี npm dependencies สำหรับแอปนี้ Node 20 ขึ้นไป

ตั้ง Environment variables โดย scope ต้องรวม Functions:

| ชื่อ | ค่า |
|---|---|
| APPS_SCRIPT_URL | URL Web App /exec จาก Apps Script |
| POS_API_KEY | ค่าเดียวกับ Script Properties |
| POS_SESSION_SECRET | รหัสสุ่มอีกชุดอย่างน้อย 32 ตัวอักษร แนะนำให้ตั้งแยก หากไม่ตั้งจะใช้ POS_API_KEY |

Publish directory: public
Functions directory: netlify/functions
Build command: เว้นว่าง
หลังเพิ่ม/แก้ environment variables ให้ deploy ใหม่
อย่าใส่ API key / token / PIN ลงไฟล์หน้าเว็บหรือ Git
มี .gitignore ตัด .netlify ออกจาก Git แล้ว

## ขั้นตอนใช้งานจริง

1. ทีมงานสร้างใบเบิกออกบูธในหน้าสต็อกเดิม เลือกสินค้า จำนวน และ Exp แล้วกดสร้าง/เบิก ระบบเดิมตัดคลังกลางตามเดิม
2. ในเว็บ POS ใหม่ เมนูจัดการ → บันทึกลิงก์ Web App สต็อกเดิมไว้สำหรับเปิดสร้างบูธ/คืนสินค้า
3. กดรีเฟรชใน POS จะเห็นใบเบิกบูธที่ยังเปิดอยู่ เลือกใบเบิกนั้น ไม่ต้องสร้างบูธซ้ำใน POS
4. ตรวจรับหน้างานแยกตาม SKU และ Exp ต้องกรอกจำนวนจริงเองครบทุกล็อต หากไม่ตรงให้แอดมินแก้ใบเบิก/คืนในระบบเดิมก่อน
5. เลือกสินค้าจากบูธ ระบุราคาขายจริง รับเงินตามช่องทาง และแนบสลิปได้แต่ไม่บังคับ
6. ยืนยันรับเงิน ระบบลงบิล V11 แถวเดียวเป็นหลักฐานหลัก มีรายการและการตัดยอดบูธใน JSON เดียวกัน สต็อกบูธคำนวณจากใบเบิก − คืน − ขายที่ยังไม่ยกเลิก จึงไม่ตัดคลังกลางซ้ำ
7. กลุ่มใหม่ได้รับรายการขายสะสมของบูธนั้นในวันนั้นเท่านั้น แสดงแต่ละบิลเรียงลำดับพร้อมสินค้าราคาและยอดรวม
8. ปิดรายวัน: นับสินค้าคงเหลือและเงินรับจริงทุกช่องทาง สรุปจำนวนขายและยอดเงิน มีส่วนต่างต้องบอสเข้าสู่ระบบและระบุเหตุผล ปิดแล้วเพิ่มบิลวันเดียวกันไม่ได้ วันถัดไปขายต่อได้อัตโนมัติ
9. จบบูธและคืนสินค้าผ่านหน้าสต็อกเดิม ระบบจะกันคืนเกินยอดที่เหลือหลังขาย V11 ยอดขายใน SalesLog เดิมยังลงตอนปิดใบเบิกตามกลไกเดิม ไม่ลงซ้ำทุกบิล
10. ยกเลิกบิลได้โดยแอดมินเฉพาะบิลวันนี้ก่อนปิดวัน คืนจำนวนให้บูธและส่งยอดสะสมที่แก้ไขเข้ากลุ่ม

## รูปสินค้า / ไฟล์แนบ

- แอดมินเข้า จัดการ → รูปสินค้าและราคาขายแนะนำ เพื่อเพิ่มรูป/ราคาได้
- รูปสินค้าไม่บังคับ ถ้าไม่มีจะแสดงภาพแทนและระบุว่าเป็นภาพแทน
- อัปโหลดรูปสินค้า: JPG / PNG / WEBP ไม่เกิน 2 MB ระบบเปิดไฟล์รูปสินค้านั้นแบบ Anyone with link เพื่อแสดงบนเว็บ
- รูปแนบบิล: ไม่บังคับ รองรับประเภทและขนาดเดียวกัน ไม่ตั้งไฟล์เป็นสาธารณะ บันทึก Google Drive file ID ไว้ในรายการ PHOTO และเชื่อม photoId ในบิล SALE
- ผู้ดูแลตรวจรูปแนบได้จากตาราง LilbullePOS_V11 โดยค้น photoId ของบิลแล้วเปิด URL ในแถว PHOTO ต้องมีสิทธิ์เข้า Drive
- ไม่แนบรูปก็ขายได้ ไม่ส่งรูปสลิปเข้ากลุ่ม LINE

## กรณีเน็ตขาด / ข้อความ LINE ค้าง

- หน้าร้านต้องมีอินเทอร์เน็ตจึงขายจริงได้ ไม่รองรับขายออฟไลน์
- ระหว่างบันทึก หน้าเว็บเก็บ requestId และบิลไว้ในเครื่องจนได้ผลตอบรับแน่ชัด ป้องกันคลิกซ้ำหรือ retry ซ้ำ
- หากไม่แน่ใจว่าบันทึกแล้วหรือยัง ให้กด “ตรวจสอบ / ส่งรายการเดิมซ้ำ” อย่าเปลี่ยนเครื่องหรือล้างข้อมูลเบราว์เซอร์ก่อนตรวจสอบ
- หากบิลสำเร็จแต่ LINE ส่งไม่ผ่าน จะขึ้นจำนวนข้อความรอส่ง แอดมินกด “ส่งข้อความ LINE ที่ค้างอีกครั้ง” ได้
- รายการสะสมแบ่งข้อความอัตโนมัติ และใช้ LINE retry key คงที่ต่อชุดข้อความ อายุการกันซ้ำเป็นไปตาม LINE ถ้าค้างนานมากต้องตรวจประวัติก่อน retry
- หากข้อความสะสมใหญ่เกินขนาดเซลล์ชีท ระบบส่งยอดรวมพร้อมให้ดูรายการเต็มบนหน้า POS แทน
- รับประกันการกันซ้ำในบิลด้วย ledger/requestId ส่วน LINE ขึ้นกับสถานะและข้อจำกัดผู้ให้บริการ

## ขอบเขตการย้ายจาก POS รุ่นเก่า

ไม่ย้ายบิลเดิมอัตโนมัติ และไม่ใช้สต็อกจำลองของรุ่นเก่ามาเป็นของจริง
ถ้าใบเบิกมีบิล PAID รุ่นเก่าผูกอยู่ จะบล็อกตรวจรับ V11 เพื่อให้ผู้ดูแลตรวจย้ายยอดก่อน
แนะนำเริ่มทดลองขายจริงด้วยใบเบิกบูธใหม่ที่ยังไม่มียอดขายใน POS เก่า
การเติมสินค้าเข้าบูธหลังตรวจรับยังใช้กระบวนการเดิมให้ผู้ดูแลตรวจทาน ชุดนี้ไม่เพิ่มฟอร์มเติมสินค้าระหว่างบูธแยกต่างหาก
ระบบแยกหน้าร้านจากระบบเดิม แต่ข้อมูลและ lock อยู่ใน Apps Script เดียวกัน

## ผลการตรวจสอบและสิ่งที่ต้องทดสอบจริง

ผ่านชุดทดสอบอัตโนมัติ 15 กรณี: ตรวจรับก่อนขาย / จำนวนไม่ตรง / FEFO / ไม่ตัดคลังกลางซ้ำ / requestId ซ้ำ / ขายเกิน / SKU ซ้ำในบิล / จำนวนราคาไม่ถูกต้อง / สิทธิ์ยกเลิก / คืนสต็อกบูธ / จำนวนคืนแยกล็อต / ปิดวัน / ส่วนต่าง / บิลรุ่นเก่า / ป้องกันปลอมสิทธิ์ / LINE ล้มเหลวแล้วบิลไม่หาย (บางกรณีรวมอยู่ในข้อทดสอบเดียว)
ผ่านตรวจ syntax ของ Code.gs, BoothPOS_V11.gs และ JavaScript หน้าเว็บ
ยังไม่ได้ทดสอบภาพและการกดบนเบราว์เซอร์จริงในสภาพแวดล้อมนี้: เบราว์เซอร์เชื่อมเซิร์ฟเวอร์ทดสอบไม่ได้
ยังไม่ได้ทดสอบเชื่อม Google Sheets, Drive, LINE หรือ Netlify จริง
ก่อนเปิดใช้งาน ให้ทดสอบด้วยใบเบิกใหม่จำนวนเล็ก ตรวจยอดก่อนและหลังขาย 1 บิล ลองยกเลิก 1 บิล แล้วปิดวันและคืนบูธ
