LIL BULLE — WAREHOUSE V11.3 + BOOTH POS V12.2
Date: 2026-11-10

สำคัญ: ยังไม่ได้ Deploy ขึ้นเว็บจริง / ไม่ได้แก้ค่าของ Stock จริง
ใช้ไฟล์ 2 ไฟล์ที่มาจากผู้ใช้ล่าสุด ไม่ใช่ V10.42 เก่า

ไฟล์ติดตั้ง
1) LilBulle_Code_V11.3_WAREHOUSE_LOT.gs : ใช้แทนเนื้อหา Code.gs เดิมทั้งไฟล์
2) LilBulle_BoothPOS_V12.2_REVENUE_AUDIT_ONLY.gs : ใช้แทนเนื้อหาของไฟล์ BoothPOS_V11.gs เดิมทั้งไฟล์ (ไม่ใช่สร้างไฟล์ใหม่ที่ชื่อซ้ำและมีฟังก์ชันซ้ำ)

อย่าลบหรือแทนที่ Index.html, POS.html, Script Properties หรือไฟล์อื่น
อย่ารัน saveEventReturn ใน Apps Script Editor โดยตรง (ต้องส่ง payload จากหน้าเว็บ)

การทำงานใหม่
- คลังกลาง: พนักงานเบิกจริงจาก EventIssue ตาม EXP ที่เลือก จะลด Stock เฉพาะครั้งนั้น
- POS: เริ่มต้นจากยอดตรวจรับจริงของบูท จากนั้นบันทึกจำนวนเติมใน ledger LilbullePOS_V11 เท่านั้น ไม่เขียน Stock, EventIssue, AuditLog
- การเติม POS รอพนักงานกดยืนยันรับสินค้าแล้วจึงเพิ่มยอดจำลองในบูท
- ถ้ามีการนำของออกจากคลังจริง ต้องบันทึกเบิกเพิ่มในระบบคลังต่างหาก (อย่าหักด้วย POS ซ้ำ)
- POS ขาย: บันทึกเงิน/จำนวน; หากยอดจำลองไม่พอให้ลงเป็นล็อตยังไม่ระบุ EXP เพื่อแจ้งส่วนต่างในรายงาน ไม่บล็อกยอดขาย ไม่แตะคลัง
- คลังคืน: ใช้เพียงเลขเบิก + SKU + EXP และยอดเบิกสะสมลบยอดคืนสะสม; ไม่หักยอดขาย/แจก/รอโอนของ POS
- คลังปิดงาน: ต้องกดปิดเอง; คำนวณยอดสินค้าสุทธิจากยอดเบิก-คืนจริงเพื่อรายงานเท่านั้น ไม่หัก Stock รอบที่สอง
- POS ปิดวัน: มีรายงานยอดขายจริงเทียบกับยอดที่ตรวจนับ และจำนวนคงเหลือจำลอง ไม่บันทึกคลัง

การติดตั้งบน iPad
1. สำรองไฟล์ Code.gs และ BoothPOS_V11.gs เดิมก่อน (เช่น copy ข้อความลง Notes/Drive)
2. เปิด script.google.com ใน Safari โหมดเว็บไซต์เดสก์ท็อป
3. แทนเนื้อหา Code.gs ด้วยไฟล์ 1; แทนเนื้อหาไฟล์ส่วนขยาย POS ด้วยไฟล์ 2
4. Save > Deploy > Manage deployments > Edit > New version > Deploy
5. ถ้า POS อยู่ Netlify และเรียก Apps Script API ต้องตรวจการตั้งค่า endpoint และหน้าจอจริงเพิ่มเติม; ไฟล์นี้ไม่ได้เปลี่ยน Netlify frontend

ทดสอบก่อนเริ่มขายจริง
A. ใช้สำเนา Google Sheet และโปรเจกต์ทดสอบ ไม่ทดลองเบิกจริงในคลังจริง
B. เปิดใบเบิก 2 EXP และบันทึกจำนวนแยกล็อต
C. ตรวจรับเข้า POS ด้วยยอดนับ; ขาย 1 บิล; เติม POS เพิ่มโดยไม่มีการเขียน Stock
D. ทำใบเบิกเพิ่มจากระบบคลังแยก แล้วตรวจว่า POS ไม่นับซ้ำ
E. คืนสินค้าแยก EXP และยืนยันว่าไม่ถูกยอดขาย POS ลดเพดานคืน
F. ปิดวัน POS พร้อมส่วนต่าง; ปิดใบเบิกคลัง; ตรวจว่าไม่มีการหัก Stock ซ้ำ
G. ตรวจ EventIssue/EventReturn/Stock/AuditLog และ POS ledger ก่อนเผยแพร่ใช้งานจริง

สถานะการตรวจ: ผ่าน Node.js syntax 2 ไฟล์, ผ่านการทดสอบจำลอง POS 4 ข้อ และคลัง 6 ข้อ
ข้อจำกัด: ไม่ได้ทดสอบหน้า Index.html/Netlify UI หรือ Deploy/Google Apps Script runtime จริง

ขอบเขต: มีการเปลี่ยนให้ POS แบบใหม่ไม่ใช่ตัวหัก Stock อัตโนมัติ. พนักงานต้องดำเนินรายการเบิกเพิ่มจริงผ่านระบบคลังเองเสมอ.
กรณี old RESTOCK ที่เคยตัด Stock อยู่แล้ว: ห้ามนำมาบันทึกใหม่ซ้ำ ต้องตรวจย้อนหลังเป็นรายงาน.
